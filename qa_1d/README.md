# 一维逐件锯缝验收

新增路线：`onedimensional-kerf`、`ffd-1d`、`bfd-1d`。三条路线均只接受最少根数目标 `bins`，整数长度、整数非负锯缝；不接受非零间距、非零边距或缺陷区域。原来的 `onedimensional` 仍不计锯缝，输入非零锯缝会被拒绝。

统一模型为每件成品占用 `length + kerf`，原料容量保持原长 `L`。每件尾部都预留一刀，末件也占用完整锯缝。这是保守模型，不含端头修边、夹持余量、斜切、余料库存或机器切割顺序。

原生路线将变换后的整数长度传给真实 PackingSolver 一维模块，保留 `solver_instance.json` 与 `solver_solution.csv`；返回时把成品长度恢复为原始长度，单独输出 `cuts`。FFD 按递减长度放入第一个容纳的原料；BFD 选择放入后剩余长度最少的原料。二者对同长零件和同余量原料使用稳定输入顺序打破平局。

`cuts` 每件一项，包括零宽切口，字段包括对应的 `item_index`、`item_id`、占用区间 `start/end`、`width` 和显示中心线 `x1/y1/x2/y2`。独立校验从原始输入重新计算成品长度与尾部锯缝，检查整数坐标、原料边界、占用区间重叠、切口对应关系，再结合原有形状、方向与需求数量检查。不使用结果自报的锯缝或可行性作为证明。

验收命令：

```powershell
.\.venv\Scripts\python.exe test_engine_1d.py
```

证据：`results.json` 记录每次真实调用的输入预算、耗时和指标；`tamper_checks.json` 记录 14 种篡改全部被拒绝；`runs/` 保存每次规范化输入、结果以及原生路线证书。每次原生求解预算为 1 秒。

边界用例验证：一根长度 10 的原料上，两件长度 5 在零锯缝时可排完；锯缝为 1 时一根无法完成，两根可完成。长度 10 的成品加锯缝 2 需要容量至少 12，不能因为它是末件而省略锯缝。额外验证了重复原料模式、字符串零件 ID、数量、原始路线回归和合成 6 米预设的三路线比较。

这些记录属于合成实例与软件实现验收，不是工厂订单实测、全局最优证明或完整工业加工验收。
