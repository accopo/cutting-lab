## 2026-10-16 引擎资源加载恢复

用户报告 Worker 的 `importScripts(packingsolver.js)` 加载失败。检查时线上文件返回 HTTP 200，115288 字节，SHA-256 与固定官方版本一致；当时失败的具体网络或浏览器原因不能仅凭截图还原。

改为先下载与校验引擎文件，按应用作用域和官方版本缓存，再启动 pthread。相同版本的并发请求复用下载，瞬时错误最多重试三次，缓存不可写时允许继续使用验证过的在线文件。主 Worker 与 pthread 脚本均保留有界导入恢复；pthread 引导仍同步执行。JS/WASM 出错显示中文资源名与重试提示。已隔离的回访页面会注册新 Service Worker，不清理历史、不强制重载其输入。

- 新增 26 项加载器故障测试、15 项 Service Worker 测试，全部通过；包括真实文件哈希、32 路并发、缓存不可用/挂起、超时、永久失败、旧控制器更新和首次加载循环保护。
- 原有 20 项任务生命周期、11 条 WASM 实际证书、4 项发布保护检查通过；构建资源哈希验证通过。
- 浏览器故障注入：`127.0.0.1:8769/cutting-lab/?runtime=browser`，JS 和 WASM 各自前两次请求人为返回 HTTP 503，第三次成功。无需用户手动刷新，Shirts 原始方向 10 秒得到 99/99、84.54%、长度 63.87，21 次事件/6 份读取布局，独立几何校验通过。
- 同页随后运行三维混合箱：24/24、1 容器、78%，约 0.02 秒，校验通过。服务器计数未增加新的引擎文件请求，确认线程与后续任务复用了缓存。

这验证了上述明确故障与环境中的恢复能力，不代表能绕过持续的网络阻断或浏览器安全策略。
